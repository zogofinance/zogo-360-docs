# Zogo 360 Flutter Implementation Guide

This guide explains how to embed Zogo 360 in a Flutter mobile app. The complete
example app supports iOS and Android and reproduces all six BasicJS examples.

## Package Overview

The example uses Flutter's official `webview_flutter` package, which renders a
native `WKWebView` on iOS and a native system WebView on Android. The integration
has three small building blocks:

- **`Zogo360Config`** builds the Zogo initialization payload.
- **`Zogo360Controller`** supports delayed initialization and outgoing events.
- **`Zogo360WebView`** owns the WebView and JavaScript message bridge.

Zogo 360 runs in its standard iframe. A minimal wrapper page forwards messages
between that iframe and Flutter's JavaScript channel.

## Requirements

- Flutter 3.44 or newer
- iOS or Android development tooling
- A Zogo user token generated by your backend

## Installation

Add the WebView package to your Flutter app:

```bash
flutter pub add webview_flutter
```

If your app handles Zogo `OPEN_URL` events externally, also add:

```bash
flutter pub add url_launcher
```

Android requires the Internet permission in `android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

Add iOS usage descriptions for any camera, microphone, or location features
enabled for your Zogo experience.

## Authentication

**Never put Zogo API credentials in a Flutter app.** Generate a short-lived user
token on your backend with `POST https://api.zogo.com/sdk/user`, return only that
user token to the app, and keep it in memory where possible.

The example accepts a token on its home screen. For local development only, it
can also be supplied with `--dart-define=ZOGO_TOKEN=...`.

## Basic Implementation

Create the WebView with a backend-generated token:

```dart
Zogo360WebView(
  config: Zogo360Config(token: userToken),
)
```

When Zogo sends `REQUEST_INITIALIZATION`, the component responds with:

```dart
{
  'type': 'INITIALIZE',
  'payload': {
    'user_auth_token': userToken,
    'widget_type': 'full_experience',
  },
}
```

See [`zogo_360_webview.dart`](Flutter%20Examples/lib/zogo_360_webview.dart) for
the complete, commented bridge implementation.

## Message Communication

The bridge performs the following flow:

1. The native WebView loads a small local HTML wrapper.
2. The wrapper loads `https://360.zogo.com/` in an iframe.
3. Iframe messages are accepted only when their origin exactly matches
   `https://360.zogo.com`.
4. Valid messages are forwarded to Flutter through `NativeInterface`.
5. Flutter sends responses with `runJavaScript`, and the wrapper forwards them
   to the iframe with a restricted target origin.

Listen for Zogo events with `onMessage`:

```dart
Zogo360WebView(
  config: Zogo360Config(token: userToken),
  onMessage: (message) {
    switch (message.type) {
      case 'OPEN_URL':
        // Open message.payload['url'] with url_launcher.
      case 'EXIT_REQUESTED':
        // Return to the previous Flutter page.
      case 'ERROR':
        // Show or report the integration error.
    }
  },
)
```

See the [Zogo 360 Events Reference](../Additional%20Resources/Zogo%20360%20Events.md)
for the complete protocol.

## Delayed Initialization

Set `autoInitialize` to `false` and provide a controller:

```dart
final controller = Zogo360Controller();

Zogo360WebView(
  config: Zogo360Config(token: userToken),
  controller: controller,
  autoInitialize: false,
)

// Call after consent or another application-specific condition.
controller.initialize();
```

The controller safely waits until Zogo requests initialization before sending
the payload.

## Module and Skill Deep Links

Use `widget_type: deep_link` with either a module ID or skill ID:

```dart
Zogo360Config(
  token: userToken,
  widgetType: 'deep_link',
  moduleId: '994850',
)
```

```dart
Zogo360Config(
  token: userToken,
  widgetType: 'deep_link',
  skillId: '1',
)
```

Handle `EXIT_REQUESTED` to dismiss the WebView and return users to your native
Flutter navigation flow.

## HTML5 Audio

Audio inside Zogo's iframe is rendered by the native WebView. Flutter does not
need to copy or pipe HTML5 audio into a separate native player. iOS and Android
media policies still apply: playback may require a user gesture, and device
volume, silent mode, audio focus, or another active audio session can affect it.

The example grants iframe microphone access but does not request autoplay. This
keeps standard WebView media behavior and allows playback initiated by the user.

```bash
cd "examples/Flutter Examples"
flutter pub get
flutter run
```

Enter a valid backend-generated user token and select an example from the home
screen. Run `flutter analyze` and `flutter test` to verify the project.

## Security Best Practices

1. Generate tokens on your backend; never ship Zogo API credentials in the app.
2. Do not log or persist user tokens unless your security design requires it.
3. Validate iframe message origins exactly rather than using substring matches.
4. Keep all WebView traffic on HTTPS.
5. Validate external URLs before opening them in production applications.
